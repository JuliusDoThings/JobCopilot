# S4-VAL-001 execution evidence

Reference corpus: `lib/dev-bench/corpus.json`, version `S4-VAL-001-v1`.
The expectations were authored as business requirements before executing the
service. No expectation was relaxed after observing an API result.

## Real HTTP integration

`S4-VAL-001-live.json` records all twelve scenarios through the development
Next.js proxy and the real local FastAPI process: **11 conforming, 1 discrepancy,
0 not executed**. VAL-007 expects an explicit naturally phrased experience to
be usable. The lexical engine instead requests clarification. This discrepancy
is retained intentionally and is not a comparison-test failure.

`S4-VAL-001-unavailable.json` records the CLI report after FastAPI was stopped:
all twelve cases are **not executed**, exit code 2. The development proxy was
also called with FastAPI stopped and returned `not_executed`. No mocked API
was used in these HTTP execution reports.

Other HTTP checks: rendered development page contains the scenario cards;
unknown scenario IDs return 422; cross-origin requests return 403. A production
server started with the opt-in flag still returns 404 for both diagnostic page
and proxy; the response page does not contain the scenario corpus.

The CLI reads the same versioned corpus and compiles the same TypeScript runner
and comparator as the UI using the existing TypeScript development dependency.
See `frontend/README.md` for exact reproduction commands and exit codes.

## Automated checks and limits

The backend suite passes 452 tests. The frontend suite covers comparator
invariants, all corpus expectations, transport failures, timeout, malformed and
oversized responses, development/production access, exact Host/Origin handling,
UI execution state, stale-result invalidation and JSON export. CI results for
the final PR commit are linked in the PR description.

The local environment uses Node 24, while CI uses the repository's Node 22.
Local Next.js compilation and HTTP checks required a scratch-only compatibility
wrapper for unavailable `/proc` memory metrics. This wrapper changes memory
telemetry only, is not committed, and is not needed in normal local development
or CI. No application behavior or test assertions were bypassed.

A browser-based visual inspection was not completed: Chromium was absent and
its download failed in this execution environment. React component tests and
real HTTP/SSR checks passed; neither proves browser layout or mobile rendering.
No screenshot is offered as evidence. Browser visual review remains available
to the Product Owner by launching the local bench.

No backend logic, deployment configuration, Azure resource, secret, dependency
or public hosting was changed. Reports contain only the fixed synthetic corpus
and sanitized diagnostics. They are editable execution records, not cryptographic
attestations or proof of the truth of a candidate's career claims.
